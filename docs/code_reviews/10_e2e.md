## Findings

### Already caught and fixed before this pass: journal dedup by filename, not path

`Journal.load_processed()` and `Watcher.rescan()` deduped the restart-skip set by `Path.name`
instead of full source path. The integration suite's `test_club_scenario_second_run_collides_with_first`
(a second card whose files share filenames — but not paths — with photos already journaled
under `dest_root`) caught this directly: the second card's files were silently dropped by
`rescan` before ever reaching `mover.py`'s collision-safe suffixing. `prompts/09_watcher_pipeline.md`
specifies dedup by path, not name. Fixed in `7fafeb9`: `load_processed()` now returns full
source path strings, `rescan()` compares `str(path)` against them, and `tests/test_journal.py`
/ `tests/test_watcher.py` were updated (plus a same-name-different-path regression case added
to each). Verified the fix is correct and narrowly scoped — no further action needed here.

### No further must-fix issues found

Checked against the review checklist:

- **File immutability** — helpers only ever `write_bytes` to newly created files under
  `tmp_path`; real `samples/` fixtures are copied via `shutil.copy2` into the tmp import dir,
  never opened for writing at their source location. `move_group`'s `dry_run` branch performs
  no filesystem writes at all (verified by reading `mover.py`), matching the dry-run test's
  "filesystem untouched" assertion.
- **Safety** — collision suffixing and journal-append-not-overwrite are exercised by the
  second-run scenario; the fix above closes the one real gap.
- **Cross-platform** — `list_tree` normalises to POSIX-style relative paths for snapshot
  comparison; no OS-specific assumptions found in the new code.
- **Tests** — assertions are concrete (full directory-tree snapshots, byte-identity checks,
  per-file journal status/tag-id checks, exit codes, log content), not tautological. All
  `prompts/10_e2e.md` requirements are covered: fixture builder with real pagination (page
  size 2), exact-boundary/between-tags/no-EXIF/RAW+JPEG cases, real Lightroom sample EXIF via
  `samples/`, full-tree + byte-identity + journal + CLI summary/exit-code assertions, second-run
  collision behaviour, dry-run parity, and the `integration` marker (confirmed CI's
  `.github/workflows/ci.yml` runs `pytest -q` unfiltered on all three OSes, so these still run
  there; `-m "not integration"` cleanly deselects them locally with no warnings). Spot-checked
  the real sample EXIF values against the hardcoded tag windows in the Club/InternationalClub
  scenarios (via `exifread`) — all fall correctly inside their intended tag's UTC window after
  `Europe/London` localisation, none are accidentally boundary-adjacent by luck.
- **Standards** — `ruff check`, `ruff format --check`, `mypy src/`, and `pytest -q` all clean
  (443 passed, 1 pre-existing skip); `-m integration` selects exactly 5, `-m "not integration"`
  deselects exactly those 5.
