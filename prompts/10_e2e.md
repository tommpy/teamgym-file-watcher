# Step 10 — End-to-end integration tests

Read `prompts/rules/testing.md`. This step proves the whole pipeline against a faked API and
real (tmp) filesystem.

## Goal
`tests/integration/` exercising `process-once` end-to-end for all three competition types.

## Requirements
1. Fixture builder: construct a fake competition scenario — tag timelines (closed + one open
   tag) for International, Club, and InternationalClub — served via pytest-httpx with real
   pagination (page size 2 to force multi-page) and a canned auth token; tiny real JPEGs
   with controlled `DateTimeOriginal` + `OffsetTimeOriginal` values spanning the tag
   windows, including: exact-boundary photo, between-tags photo (→ Random), photo with no
   EXIF date (→ Random + warning journaled), RAW+JPEG companion pair (fake RAW bytes are
   fine — capture time comes from the JPEG if the RAW is unreadable; the pair must land
   together). Also copy the real Lightroom JPEGs from `samples/` through the pipeline to
   prove real-world EXIF parses.
2. Run `process-once` via `CliRunner` against tmp import/dest dirs. Assert:
   - the COMPLETE resulting directory tree matches an explicit expected snapshot (paths
     including Random branches, Awards branch, composite "Club - Team" segments);
   - moved files are byte-identical to the originals (the watcher never modifies files);
   - journal contents (statuses, tag ids) and CLI summary/exit code;
   - import dir left with nothing but ignored files.
3. A second `process-once` run over the same dest (fresh import files with colliding names)
   → collision suffixes, no overwrites, journal appends.
4. Dry-run variant: identical logging expectations, filesystem untouched.
5. Mark integration tests so they run in CI on all three OSes but can be skipped locally
   with `-m "not integration"`.

## Definition of done
Checks pass on the full suite; commit `test: end-to-end integration coverage`.
